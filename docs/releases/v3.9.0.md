## What's New

MUSE 3.9 makes the multi-lane team from 3.8 lighter to run. It changes rules, prompt
templates and documentation only; the continuity runtime, installer and Python tools are
unchanged. The changes come from comparing four working modes in one long-running
deployment and keeping the one that stopped producing session churn.

### 🗜 Compaction first, not session swaps

Lanes no longer start a new session because their context reached a percentage. They let
the client compact, keep a rolling checkpoint, and update it at about 80% context without
stopping. A fresh session is for three cases only: an account switch, a clearly confused
session, or an expected idle wait of more than 60 minutes with more than 300k tokens of
context. The old "swap at 70%" and "orchestrator hands off at 70–76%" rules are removed.

### 🧩 Subagents inside a lane

Work that has to run in parallel inside one lane goes to that lane's subagents, not to
extra sessions. Prefer a few lanes with clear owners to many that share one owner.

### 🧹 A leaner `/handoff save`

A save now writes the lane checkpoint, the relay snapshot and the user's new decisions
(memory). Vault writes, `vault_coverage_check.py` and `memory_audit.py` run once a day in
the orchestrator's evening report ("Daily maintenance"). `/save` and `/bye` are unchanged.

### 🧪 Full tests in CI, and a load guard that reads memory pressure

- Full test suites run in CI or on a remote runner. The heavy lock covers only what has to
  stay local: production builds, timing-sensitive tests, virtual machines and simulators.
- macOS allocates swap files on demand and is slow to release them, so "free swap above
  2 GB" cannot be held. The guard now trips when free swap is below 2 GB **and** free memory
  is below 30% (`memory_pressure`), or when the 1-minute load is above 20. Tune the
  numbers for your machine.

### 🛡 Two operating lessons

- **Cross-session message cap.** If the client caps messages to other sessions, treat it
  as a loop guard: write the unsent messages as pending drafts in the checkpoint and send
  them after the user's next message. Do not switch channel to get around it.
- **Test browser profiles.** Open a profile directory that automation owns only with the
  automation's own launch flags (Puppeteer starts Chrome with `--use-mock-keychain
  --password-store=basic`). An ordinary browser instance cannot read the saved cookies and
  can leave every test account logged out.

### Install or upgrade

```bash
bash scripts/install.sh --tool claude --target /path/to/project
bash scripts/install.sh --tool codex --target /path/to/project
```

Upgrading a 3.8.0 install rewrites the orchestration skill's reference and template
files, the `handoff` workflow and the install state, and nothing else. No configuration
key was added; existing `.muse/orchestration.json` files keep working. Projects without
one keep the single-lane behaviour of 3.7.1.

### Boundaries

The evidence behind the change is two days under the new mode, with day boundaries that
differ from the earlier phases; read it as a trend, not a benchmark (table in
`references/ACCOUNT_RELAY.md`). Machine load peaks did not improve in those two days.
Lane names, approval ids and timers never widen authority. Deployments, production data
changes, payments, external messages and deletions still need your consent in the current
session. A tool PASS is not product QA.
