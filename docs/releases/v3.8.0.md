## What's New

MUSE 3.8 lets several long-lived AI sessions work as one team. One session acts as the
orchestrator; the others are lanes you define yourself. The rules and tools come from
weeks of running about a dozen parallel lanes through repeated account switches.

### 🧭 An orchestrator and your own lanes

Describe the team in `.muse/orchestration.json`: the orchestrator plus each lane's
checkpoint file and required reads. MUSE ships no fixed lane names. The orchestrator is
the single place where decisions for you collect (at most three at a time, each with a
recommendation), keeps the board current and keeps lanes from silently stopping: every
decision becomes a board row, every package ends verified, deployed or explicitly
cancelled, stalled rows are chased, lanes that hit a usage wall are woken after the reset,
and idle lanes get their next task.

### 🔁 Account relay with `/handoff`

- `/handoff save` writes memory first, then the lane checkpoint and a relay snapshot.
- `/handoff <lane id>` in a session under the new account reads the files, re-syncs with
  the other lanes, reports and continues.
- `/handoff status` lists every lane's latest snapshot.

Saving follows a forecast: when weekly usage is expected to run out within 20 minutes, or
reaches 95%, every lane saves, then keeps working until the wall. Short usage windows
never trigger a global save; each lane keeps a one-shot timer at reset + 1 minute.
`wall_recover.py` lists unfinished subagents from the old session's local transcript when
the wall came first.

### 🌙 `/away` and `/back`

`/away` (`/托`) lets the agents decide what they are allowed to decide while you are out
and queue the rest. `/back` (`/回`) gives you one list: what was done, what was decided
for you, at most three decisions that need you, and anything only you can do.

### 🧠 Memory and guard tools

- `recall.py` searches every memory directory and checkpoint before anyone answers
  "it is not in my records".
- `memory_audit.py` checks index limits, cross-directory visibility, decision backlog,
  vault freshness and key patterns (values are never printed).
- `negative_claim_guard.py` is a Stop hook that blocks a negative memory claim made
  without running `recall.py`; `licence_stop_guard.py` is an optional policy hook that
  keeps a licence as one line of fact and sends licence limits to human review before
  production use.
- `vault_coverage_check.py` and `vault_freshness.py` check the optional Obsidian vault.

### ⏱ Timer templates

Patrol, quota sentinel and twice-daily report prompts for the orchestrator, with timer
hygiene for handoffs and retired sessions.

### Install or upgrade

```bash
bash scripts/install.sh --tool claude --target /path/to/project
bash scripts/install.sh --tool codex --target /path/to/project
```

Then copy `.agent/skills/core/muse-orchestration/templates/orchestration.example.json`
to `.muse/orchestration.json` and describe your lanes. Projects without it keep the
single-lane behaviour of 3.7.1.

### Boundaries

Lane names, approval ids and timers never widen authority. Deployments, production data
changes, payments, external messages and deletions still need your consent in the
current session. A tool PASS is not product QA.
